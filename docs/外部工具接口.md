# 外部工具接口（cando-tools/1）

给合作开发者看的约定。读完这一页，就能用任何语言（例如 Python）写工具接进 CanDo 可为，不需要看 CanDo 的代码。

同一份约定的机器可读版是 `docs/cando-tools.openapi.json`（OpenAPI 3.0）：给程序和 AI 编程工具看，可以导入 Swagger、Postman，或用来生成代码。两份说法不一致时，以 OpenAPI 文件为准——CanDo 的测试 `TestExtToolsOpenAPIContract` 保证它和程序里实际执行的规则一致。

## 一句话

CanDo 是航母，外部工具服务是飞机。航母负责指挥、判断、安全和甲板（用户的文件）；飞机只执行分配给它的那一件事，然后回到甲板。两边之间只有一条通道：本机 HTTP。

## 分工

| CanDo（航母）负责 | 外部工具服务（飞机）负责 |
|---|---|
| 智能体循环：决定下一步做什么、调用哪个工具 | 把一件具体的事做好：画图、插图、排版、解析模板…… |
| 系统提示、记忆、技能、对话历史 | 工具的名字、说明、参数说明（写在工具清单里） |
| 论文契约、审稿人攻击、偏离检查、导出前确认、老师审阅等写作流程 | —— |
| 用户的文件：在授权文件夹里读、确认后写、备份、撤销 | 只处理收到的文件内容，把结果交回来 |
| 权限：每个工具第一次调用都请用户确认 | —— |
| 界面 | —— |

外部工具服务收不到系统提示、对话历史、记忆和用户资料，只收到这一次调用声明过的参数。它也碰不到用户的磁盘。这是有意设计的：飞机越简单，两边越不容易互相拖累；出了问题也能一眼看出是哪边的事。

## 快速开始

1. 运行示例：`python tools/extool/example_server.py`（只用 Python 标准库，默认 `http://127.0.0.1:8765`）。
2. 在 CanDo 里打开「AI 助手 → 能力中心」，点“接入工具服务”，短名填 `fig`，地址填 `http://127.0.0.1:8765`，点“接入”。接好后，你的每个工具都会在能力中心里显示成一张卡片。
3. 对智能体说“把 3、5、2 画成柱状图存到我的论文文件夹”。它会调用 `ext.fig.bar_chart`，第一次会请你确认；生成的 SVG 作为修改建议，由你确认后才保存。

加自己的工具：在 `example_server.py` 里写一个函数，上面加 `@tool(...)`，然后重启服务。CanDo 那边自动发现（最多 20 秒缓存），不用改 CanDo 的任何代码。

## 约定

只有两个地址。数据格式为 JSON（UTF-8）。

### GET /tools：工具清单

```json
{
  "protocol": "cando-tools/1",
  "service": {"name": "画图服务", "version": "0.3"},
  "tools": [
    {
      "name": "bar_chart",
      "title": "画柱状图",
      "description": "把一组数字画成 SVG 柱状图",
      "example": "把 3、5、2 画成柱状图",
      "params": {
        "type": "object",
        "properties": {
          "values": {"type": "array", "description": "数值列表"},
          "data":   {"type": "string", "format": "cando-file", "description": "数据文件"}
        },
        "required": ["values"]
      },
      "makes_files": true,
      "timeout": 60
    }
  ]
}
```

- `protocol` 必须以 `cando-tools/1` 开头，否则 CanDo 不接。
- `name`：小写字母开头，只含小写字母、数字、下划线，最多 40 个字符。不合规或重复的工具会被忽略。智能体看到的全名是 `ext.<短名>.<name>`，其中短名由用户接入时决定（飞机不能冒充航母自带的工具）。
- `title` 最多 30 字，`description` 最多 300 字，参数说明最多 80 字，超出部分会被截掉。这些文字会给智能体看，所以要写清楚“什么时候该用这个工具”。
- `example`（可以不给）：给用户看的一句示例，最多 120 字。它会显示在 CanDo「能力中心」这个工具的卡片上，用户点“用它”时填进智能体的输入框。写成用户会说的话，例如“把 3、5、2 画成柱状图”。
- `params` 是 JSON Schema，只用得到 `type`、`description`、`enum`、`required`，每个工具最多 20 个参数。`save_to` 和 `reason` 是 CanDo 保留的名字，不要用。
- 文件参数：`"format": "cando-file"`。智能体填的是授权文件夹里的路径，CanDo 读出文件后替换成 `{"name": "文件名", "base64": "……"}` 再发给你。每个文件最多 20 MB，一次最多 5 个。
- `makes_files: true`：表示这个工具会生成新文件。智能体可以多填一个 `save_to` 指定保存位置，默认放在输入文件旁边。
- `timeout`：秒，默认 120，最多 600。
- 每个服务最多 30 个工具。

### POST /tools/{name}：调用

请求：

```json
{"args": {"values": [3, 5, 2], "data": {"name": "data.csv", "base64": "YSwxCmIsMgo="}}, "call_id": "…"}
```

`args` 里只有你声明过的参数。`call_id` 每次都不一样，写日志时可以用。

成功：

```json
{
  "ok": true,
  "text": "画好了 3 根柱子",
  "files": [
    {"name": "chart.svg", "base64": "…"},
    {"name": "main.tex", "base64": "…", "replaces": "tex"}
  ]
}
```

- `text`：给智能体看的结果，最多 2 万字，超出部分截掉。
- `files`：可以不给。每个文件有两种情况：
  - 新文件：只给 `name` 和 `base64`。CanDo 保存到 `save_to`，如有同名文件会自动改名，不覆盖。
  - 某个输入文件的新版本：加上 `"replaces": "参数名"`，参数名必须是这次调用里的文件参数。CanDo 会检查原文件在这期间没被别人改过，先备份再替换，用户可以撤销。
- 一次最多交回 20 个文件，合计不超过 50 MB。CanDo 不保存可执行文件和脚本（`.exe .bat .cmd .ps1 .vbs .js .sh .jar .lnk .reg` 等），也不保存以 `.` 开头的文件和密钥类文件。

失败：

```json
{"ok": false, "error": "values 必须是数字列表"}
```

`error` 会原样显示给用户和智能体，所以要用中文写清楚原因。HTTP 状态码用 200 即可；返回非 200 时也按失败处理。

## CanDo 这边强制执行的规则

即使外部服务写错了、被人改了，下面这些也不会被突破：

1. 只连本机：地址必须是 `127.0.0.1`、`localhost` 或 `::1` 并带端口。不走代理，不跟随重定向，连接时会再检查一次对方确实在本机。
2. 用户确认：每个外部工具第一次被调用时，都会弹出确认，列出服务地址和要发送的参数与文件。用户可以选“允许一次”“始终允许”或“拒绝”，“始终允许”可以在能力中心里改回。无人值守的定时任务只调用设为“始终允许”的工具。
3. 最少发送：只发送工具声明过的参数；文件只能来自授权文件夹，密钥类文件不发。
4. 写入要确认：外部工具交回的文件全部是“修改建议”，用户确认后才写入；写入前备份，可撤销。
5. 内容是数据：工具说明和返回内容会被截短，智能体被告知这些是数据，不是指令。

## 版本和兼容

- 以后只加字段、不改含义，协议名保持 `cando-tools/1`。两边都要忽略看不懂的字段。
- 要做不兼容的改动时，改用 `cando-tools/2`，并且先和对方商量。
- CanDo 的测试 `TestExtToolsPythonExample` 会用真实的示例服务走一遍，保证示例和这份约定一致。

## 调试

```bash
curl http://127.0.0.1:8765/tools
curl -X POST http://127.0.0.1:8765/tools/bar_chart -H "Content-Type: application/json" \
     -d '{"args":{"values":[3,5,2]}}'
```

Windows 的 PowerShell 可以用 `Invoke-RestMethod`，也可以直接在浏览器打开 `/tools` 查看清单。

按契约自动检查（只用 Python 标准库）：

```bash
python tools/extool/check_contract.py http://127.0.0.1:8765
python tools/extool/check_contract.py http://127.0.0.1:8765 --call bar_chart --args "{\"values\": [3, 5, 2]}"
```

第一条检查工具清单和出错时的返回格式，不会运行你的任何工具；加了 `--call` 才真的调用一次，并检查返回的格式和交回的文件。“错误”是 CanDo 会拒绝或忽略的，“提醒”是会被截短或改掉的。

## 常见问题

**我想让智能体按国赛模板排版、在特定位置改句子，要改系统提示词吗？**
不用改 CanDo 的系统提示。分两种情况：
- 做事的步骤（先读模板、再分析格式、再插图……）写成 CanDo 的技能（SKILL.md，「技能」页面可以导入），智能体需要时会读取。
- 需要代码才能做好的事（解析模板 LaTeX、生成图片、按格式插入）写成工具，并把“什么时候用、注意什么”写进工具的 `description`。

**为什么不能直接给路径，让我自己读写文件？**
读写用户文件是航母的职责：权限目录、确认、备份、撤销、冲突检查都在 CanDo 这边。如果每个外部服务各做一套，就会出现两套规则，出了事说不清是谁改的文件。

**能接别的电脑上的服务，或者云端服务吗？**
现在不能。用户的论文和数据会发给工具服务，只允许本机是最稳妥的做法。以后确有需要，再单独设计（加密、身份验证、明确提示用户数据会离开本机）。

**为什么不直接用 MCP（Model Context Protocol）？**
思路是一样的：工具清单加上调用。CanDo 坚持只用 Go 标准库、零依赖，所以先用这个更简单的约定，而且字段设计和 MCP 相近（名字、说明、JSON Schema 参数）。以后需要时可以加一个 MCP 适配层，外部服务那边的函数不用改。
