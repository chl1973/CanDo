# 论坛模式 · 产品方案（第一版草案，2026-09-29）

> 上一级方案见 `docs/平台化方案.md`。本文只讲第一步“校内联盟版”要做什么、怎么做，以及还要你定的事。

## 一、这一步要解决什么

`平台化方案.md` 里的四道门槛，现在的 CanDo 已经在帮“知识”和“规范”；“资源”和“圈子”还缺。论坛模式的第一步只做一件事：

**让几个课题组（可以是不同学校）之间互相看到对方的开放问题和经验，外组的学生能认领问题、做出来能署名。**

跑通这一件事，就验证了平台最核心的假设：有老师愿意把问题放出来，有学生愿意跨组来做，署名能让双方都得到好处。

**这一步不做**：公开网站、陌生人注册、匿名评审、证据分、推荐算法、未成年人用户。这些放到后面（见“六、分几步走”）。

## 二、放什么内容（第一版只有三种）

| 内容 | 谁发 | 例子 | 从哪来 |
|---|---|---|---|
| **开放问题** | 老师（或老师批准后学生发） | “校园共享单车停放点的优化，需要一名会 Python 的同学做数据分析” | 新写 |
| **经验** | 做完项目的学生和老师 | 大创结题复盘：做得好的、踩过的坑、给后来人的建议 | 现有“经验库”（项目归档时写的复盘）一键发布 |
| **回复** | 联盟里的任何人 | 追问、建议、“我们组做过类似的” | 新写 |

以后再加（参考 Octopus 的小单元）：想法、失败的实验、数据、复现、代码、评审。

## 三、主要流程

### 1. 发布（默认不公开，发出去要点确认）
- 本机的东西默认只在本组。要发到联盟，必须点“发布到联盟”，先看预览再确认。
- **学生发的内容先交给本组老师审核**，通过了才发出去。沿用现有的“提交审核 → 通过 / 退回”流程。
- 资料原文、论文全文、个人资料**永远不发**（版权和隐私），只发自己写的文字。
- 用 AI 帮忙写的内容，自动带上“AI 辅助”标注。

### 2. 认领开放问题 → 署名
1. 外组学生看到开放问题，点“我想做”，写几句自己的情况。
2. 出题老师同意后，问题状态变成“进行中”，列出参与的人。
3. 做的过程中在问题下面回复进展；可以在自己的 CanDo 里建一个项目来做（用现有的流程、资料库、写论文功能）。
4. 做完后，出题老师确认“已完成”，并确认每个人的贡献（提出问题、做实验、写代码、写报告……，参考 CRediT 贡献分类）。
5. 确认后的贡献记录永久保存在问题下面，每个人的“作品集”里也能看到。这就是署名。

### 3. 经验共享
- 项目归档时，复盘里多一个选项“同时发布到联盟”。老师审核后发出。
- 联盟里的经验按比赛 / 项目类型（大创、挑战杯、数学建模……）分类，可以搜。

## 四、技术做法：在现有程序上加“联盟同步”

### 为什么不能让各组的电脑直接互连
不同学校的电脑都在校园网里面，外面连不进来。所以联盟需要一个大家都能连上的“中转站”；或者先用文件交换，完全不需要服务器。

### 分两档
| | 第 1 档：文件交换 | 第 2 档：中转站 |
|---|---|---|
| 怎么同步 | 发布时生成一个“联盟包”文件，通过微信 / 网盘 / U 盘发给其他组，对方导入 | 各组的 CanDo 自动把发布的内容推到中转站，再从中转站取别人的 |
| 要不要服务器 | 不要 | 要一台云服务器（最便宜的就够） |
| 实时性 | 手动，慢 | 自动，几分钟内 |
| 合规 | 不涉及公开网站 | 只给联盟成员用、不对公众开放；仍建议先问学校信息中心 |
| 用途 | 先验证“有没有人发、有没有人认领” | 验证通过后再上 |

**中转站就是同一个 CanDo 程序换一种模式运行**（例如 `CanDo -hub`），不用另写一套。以后做公开网站时，中转站就是它的起点。

### 数据怎么设计（为以后的公开平台打底）
- 每条发布的内容是一份**签过名的 JSON**：内容 ID、种类、作者（课题组 + 成员）、正文、时间、版本号。
- **每个课题组的 CanDo 第一次开启联盟时自动生成一对密钥**（Go 自带的 Ed25519）。发出去的内容都用它签名，别人收到后能验证“确实是这个组发的、没被改过”。私钥只在本机，和现有的加密密钥一起保存。
- **只增不改**：修改是发一个新版本，撤回是发一条“已撤回”记录。这样各组之间同步不会冲突，谁改了什么都有记录。
- 联盟内容单独存放，和本组的数据分开，关掉联盟不影响现有功能。
- **接口先定下来再写代码**：本机新增 `/api/forum/…`（给界面用）；中转站用 `/hub/v1/…`，从第一天起就带版本号，因为以后会有不同版本的 CanDo 同时连它。两套接口都写进 `docs/API.md`。

### 身份和权限
- 联盟成员以“课题组”为单位加入：管理员在设置里填联盟邀请码（第 2 档）或导入对方的课题组名片（第 1 档）。
- 能看到的人都是联盟里的已知成员，不是陌生人。显示“姓名 · 课题组 · 学校”。
- 每组管理员可以撤回本组发出的任何内容；收到不合适的内容可以在本组隐藏并通知对方组。

## 五、界面（原型要画的页面）
1. **联盟首页**：开放问题 / 经验 两个标签，按类型和学校筛选，搜索。
2. **开放问题详情**：问题说明、需要什么样的人、状态（招募中 / 进行中 / 已完成）、参与者和贡献、回复区、“我想做”按钮。
3. **发布**：写开放问题的表单；经验从已归档的项目里选；发布前预览；学生发布显示“等待老师审核”。
4. **老师的待办**：本组学生的发布申请、别组学生的认领申请、待确认的贡献。现在的首页“待我处理”里加这几类。
5. **我的作品集**：我参与过的问题和确认过的贡献，可以导出。
6. **设置 → 联盟**：开启 / 关闭、本组名片（导出给别的组）、已加入的课题组、导入联盟包。

## 六、分几步走
| 步骤 | 做什么 | 验证什么 |
|---|---|---|
| 0（现在） | 这份方案 + 能点击的原型（假数据，不连后端） | 给 2–3 位老师和几位学生看，问“你会不会发 / 会不会认领” |
| 1 | 本机联盟数据 + 界面 + 联盟包导入导出（第 1 档） | 2–3 个课题组真实试用一个学期：发了多少问题、多少被认领、多少完成署名 |
| 2 | 中转站自动同步（第 2 档） | 同步是否可靠，组数变多后是否好管 |
| 3 | 匿名评审、证据分、新人推荐 | 进入 `平台化方案.md` 的“公开测试版” |

每一步都开分支、提 PR，GitHub 测试通过再合并。

## 七、要你定的事
1. **第一批试用的课题组**：大概几个组、是否跨校？有没有愿意出开放问题的老师？
2. **学生发布要不要老师先审核**：建议要，第一版风险最低。
3. **完成和署名谁说了算**：建议出题老师确认，参与者可以对自己的贡献描述提出修改。
4. **叫什么**：“联盟”“论坛”“广场”“问题墙”……界面上的名字。
5. **有没有云服务器**：决定第 2 档什么时候能做；第 1 档不需要。
