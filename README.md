# CanDo 可为（原“科研竞赛工作台”）

> 用 Claude Code 继续开发：先读 `CLAUDE.md`；上 GitHub 的步骤见 `docs/GitHub与ClaudeCode.md`。下一阶段方向见 `docs/平台化方案.md`。

把课题组的科研和竞赛做成模块化流水线：流程模板 → 阶段提交与审核 → 项目资料库与有依据问答 → 论文引用核验 → 归档复盘与经验库。

- 用户安装与使用：见 `build/使用说明.txt`（会随安装包一起安装）
- 测试结果：见 `TEST_REPORT.md`

## 架构

- **单文件 Windows 程序**：Go 语言编写，只用标准库，没有任何第三方依赖。网页界面打包在程序内部（`web/`）。
- **本机服务 + 网页界面**：程序监听 18765 端口（被占用时自动顺延），启动后用系统默认浏览器打开（1.0.2 起；早期版本的 Edge 应用窗口在部分电脑上会显示空白）。同一局域网的手机用浏览器访问，可以“添加到主屏幕”。
- **数据**：`%LOCALAPPDATA%\KeyanWorkbench\data`
  - `data.json`：账号、项目、记录。每次修改都原子写入，出错时回滚
  - `chunks/`：资料切分后的片段
  - `files/`：上传的原文件
- **PDF 解析**：在浏览器端用 pdf.js（Apache-2.0）逐页提取文字，所以服务器端不需要任何组件。
- **检索**：BM25，中文用“二字组 + 单字”切分；每个命中片段会连带相邻片段一起返回，这样写在相邻段落里的适用条件也能被带上。
- **模型**：任何 OpenAI 兼容的 `/chat/completions` 接口都可以。模型必须输出结构化 JSON，后端校验每个引用 ID 是否属于本次授权检索到的片段，并检查结论里的数字。
- **引用核验**：
  - L0：用公开数据库 OpenAlex 检查参考文献是否存在，只发送题名
  - L2：对照作者上传的原文，逐句核对

## 安全要点

- 身份只认服务端会话（HttpOnly Cookie），不信任客户端传来的用户 ID；所有写请求都要带安全标记（防跨站请求伪造）；设置了严格的内容安全策略（CSP）。
- 权限规则：项目资料只有成员和指导老师能访问；个人资料只有本人能访问；无权访问和不存在一律返回 404。
- 局域网访问默认关闭，开关只能在本机修改；首次设置也只能在本机完成。
- 密码用 PBKDF2-SHA256 加密（12 万次迭代）；连续输错 5 次锁定 5 分钟。
- 资料里的文字只当作数据交给模型，模型无法借此访问其他文件。

## 构建

```bash
./build.sh
```

依赖：Go 1.22+、NSIS 3（makensis）、UTF-8 语言环境；只有修改图标或版本资源时，才需要 mingw 的 windres。

产物在 `dist/`：

- `CanDo可为_安装包_v版本号.exe`
- `CanDo可为_免安装版_v版本号.zip`
- `CanDo_安卓App_v版本号.apk`

本地开发运行：

```bash
go run . -data ./devdata -port 18800
```
